How Marreq works

Three views of the same engineering record

Structure, history, and review

Organize hierarchical requirements with metadata, comments, and immutable version history. Editing an approved requirement creates a new draft version.

  • Hierarchy and project isolation
  • Version history and structured diffs
  • Draft → Reviewed → Approved
  • Comments on requirements and versions

Coverage you can inspect

Link requirements to verifications. The matrix and coverage views highlight gaps, orphans, and suspect links after related changes.

  • Requirement ↔ verification links
  • Status indicators in the matrix
  • Suspect-link handling
  • Excel export of the matrix

REQ-043VER-019suspect

Freeze a trustworthy state

A baseline captures which requirement version was current and the traceability matrix at that moment. Baselines are immutable at the database and API level, and can be diffed against current or exported as ReqIF.

  • Immutable snapshots
  • Requirement versions + matrix
  • Diff versus current
  • ReqIF export from baseline

Run locally

Prerequisites: Docker Compose, Rust (stable), clang/libclang, and Node.js 20 for the SPA.

quick start
docker compose -f docker/docker-compose.yml up -d db
./marreq-core/scripts/db_setup.sh
./marreq-core/scripts/db_setup.sh --seed
cargo run -p marreq-server
cd frontend && npm install && npm run dev

Demo admin: alice / ChangeMe123!. Full stack on port 8080: docker compose -f docker/docker-compose.yml up -d

HTTP API overview

JSON under /api. Local default: http://127.0.0.1:8000/api. Behind Docker/Vite, use the SPA origin.

Auth

  • Session login + CSRF for mutating calls
  • Bearer tokens for headless clients and MCP

  • Verifications, matrix, coverage, baselines
  • Optional semantic search when enabled
