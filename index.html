Marreq

Open source requirements engineering

Requirements engineering, without losing traceability.

Marreq is an open-source platform for managing hierarchical requirements, verification, approvals, and immutable baselines—with ReqIF, REST APIs, and optional MCP for AI assistants.

Product

Built for engineering teams that need an audit trail

Marreq keeps requirements, verifications, and their links under one project-scoped system. Hierarchical structure, version history, review and approval, comments, and suspect-link handling stay connected—so coverage and change impact remain visible as the product evolves.

Self-host with marreq-server, use the hosted demo at app.marreq.com, or integrate through the JSON API and optional MCP server.

Features

Capabilities that stay connected

Emphasis on the workflows engineering teams use every day—not a flat feature checklist.

Core

Requirements & versioning

Hierarchical requirements with immutable version history, metadata, categories, applicability, and comments. Editing an approved requirement creates a new draft version.

  • Multi-project isolation
  • Version history & diff
  • Comments on requirements and versions
Trace

Traceability

Link requirements to verifications. Matrix and coverage views surface gaps, orphans, and suspect links when related artifacts change.

REQ-001 VER-014
Snapshot

Immutable baselines

Point-in-time snapshots of requirement versions and the traceability matrix. Baselines cannot be updated or deleted—enforced in the database and API.

Workflow

Approval workflow

Draft → Reviewed → Approved

Explicit, audit-friendly transitions for project reviewers. List filters for approved and not-approved requirements.

Interop

ReqIF & Excel

Import and export requirements via ReqIF 1.2 and Excel/CSV. Export the live project or a specific baseline for audits and releases.

API

API & automation

Project-scoped REST/JSON API with session and Bearer token auth—ready for CI, scripts, and headless clients.

AI-ready

MCP for assistants and agents

An optional Model Context Protocol server exposes a controlled subset of Marreq capabilities to compatible AI assistants. Modes range from read-only coverage and baselines to draft write and trace write—with audit events for tool calls.

Engineering requirements remain the core product. MCP is an integration surface, not a replacement for the UI or API. MCP setup docs

Requirements that evolve

Structure, history, and review in one place

Organize requirements hierarchically with categories, applicability, authors, and reviewers. Track status and approval (Draft → Reviewed → Approved), discuss with comments, and inspect version history or diffs when content changes.

  • Hierarchical parent/child relationships
  • Immutable version snapshots with structured diffs
  • Comments with optional version reference
  • Project reviewers for status and approval actions

Trace everything

See coverage between requirements and verification

Link requirements to verifications and inspect the matrix. Coverage reporting highlights requirements without tests, tests without requirements, and suspect links after related changes.

  • Requirement ↔ verification links
  • Matrix with status indicators
  • Suspect-link handling
  • Excel export of the matrix

Freeze a trustworthy state

Immutable baselines for audits and releases

Create a baseline to capture which requirement version was current and the traceability matrix at that moment. Compare a baseline snapshot against the current project state, and export ReqIF from a specific baseline when you need a frozen interchange package.

  • Immutable at database and API level
  • Requirement version + traceability snapshot
  • Diff versus current
  • ReqIF export from baseline

Run locally

Prerequisites: Docker Compose, Rust (stable), clang/libclang for Excel export, and Node.js 20 for the SPA.

quick start
# Start PostgreSQL (pgvector image via compose)
docker compose -f docker/docker-compose.yml up -d db

# Migrations (+ optional demo seed)
./marreq-core/scripts/db_setup.sh
./marreq-core/scripts/db_setup.sh --seed

# API (self-hosted): http://127.0.0.1:8000/api
cargo run -p marreq-server

# SPA (dev): http://localhost:5173 — proxies /api
cd frontend && npm install && npm run dev

Seeded demo admin: alice / ChangeMe123! (change after first login). Full Docker stack (API + SPA on port 8080): docker compose -f docker/docker-compose.yml up -d

HTTP API overview

JSON routes mount under /api. Local API default: http://127.0.0.1:8000/api. Behind Docker nginx or Vite, call the SPA origin (e.g. http://localhost:8080/api).

Auth

  • POST /auth/login, GET /auth/me, CSRF for mutating session calls
  • Bearer tokens for headless clients and MCP

Domain

  • Requirements, versions, approval, comments
  • Verifications (tests), matrix, coverage
  • Baselines and baseline-vs-current diffs
  • Optional semantic search / RAG when enabled
curl -s http://127.0.0.1:8000/api/auth/me
curl -s http://127.0.0.1:8000/api/projects

Endpoint lists evolve with the product—prefer the repository README and OpenAPI fragment over copying a homepage catalog. HTTP API contract · OpenAPI (partial) · README API section

Technology & layout

  • Backend: Rust, Rocket, Diesel, PostgreSQL (pgvector optional for embeddings)
  • Frontend: React 19, TypeScript, Vite, Tailwind CSS
  • Deployments: marreq-server (self-hosted) and marreq-cloud (hosted-style)
  • Integrations: ReqIF, Excel, optional MCP server (mcp-server/)
  • Containers: Docker Compose for db, API, SPA, optional Ollama
